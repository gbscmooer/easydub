# 面试材料（D12）：简历 bullet + 追问预案

## 简历 bullet（动词 + 方案 + 量化结果，数字见 docs/EVALUATION.md）

1. **设计"生成端限长 + 后处理变速 + 溢出重译"三级音画同步方案**，把中→外配音的
   段级溢出率从自然翻译的 38%~100% 压到 **0%**（5 类素材 × 消融实验验证），
   时长匹配率 100%。
2. **定位并修复云 TTS 固定静音缺陷**（0.2s 头 + 最长 1s 尾静音，单字配音实测
   1.51s/语音仅 0.33s），TTS 后置静音修剪，短句对齐溢出 8/13 → 1/13。
3. **实现 LatentSync 自建推理服务接入**（FastAPI 契约 + 轮询 + 断点重试），
   人脸检测分段只对出镜段做口型、单段失败自动回退；40s 真人口播
   中文配音口型成品 216s 出片（RTX 5090）。
4. **搭建评测体系与 Agent 决策闭环**：5 素材消融评测脚本一键出指标表
   （CER/字幕偏移/RT 系数/成本，单条成本 ¥0.01~0.03）；手写 MCP 服务把流水线
   注册为 3 个工具，Agent 逐段决策重译（译文硬校验 + 实测时长反推预算），
   残余溢出 1→0，决策全程落日志。
5. **自主发现并修复三处工程缺陷**：配音混音丢弃原声 → sidechaincompress 闪避
   混入 BGM（句间音乐 -91dB→-29dB 回归、配音电平不变）；提出"借空隙溢出≠真冲突"
   的 spill 重分类（超短槽位重跑白烧 2 轮 LLM → 0 调用）；TTS/重译线程池并发
   （13 段 20.0s→4.7s，4.3×），全程量化验收。
6. **量化归因驱动的时间轴与音色优化**：字幕偏移逐段统计发现云 ASR 起点系统性
   偏晚 0.15s → 起点前移补偿压到 **0.036s**（≤100ms 达成）；FFT 自相关估说话人
   基频自动选男女声（Nike 111Hz→男声、TED 216Hz→女声，原先全配男声）。
7. **十轮自主迭代把"能跑"打磨成"可运营"**：评测矩阵 49 行（素材×语言×档位×
   ASR×LLM 五维键增量合并）；E6 证明限长闭环使三模型同步指标等价；分阶段计时
   实测 30s 素材全冷 **7.1s（RT 0.24）**；BGM 闪避 A/B 演示句间响度差 **63dB**；
   Web 上传上限/任务删除/历史管理闭环，77 项测试绿。

## 追问预案（每条背后有 5 分钟深挖）

**Q1 时长对齐怎么做？为什么限幅 1.25？**
中文信息密度高，直译外语通常长 20%~40%，硬塞必超时。三层夹逼：提示词按
槽位秒数×CPS 估算字符预算（生成端）；TTS 实测后 ratio=tts/slot 分三档
（fit/atempo/overflow）；仍超时的按预算×0.75^轮次重译（最多 2 轮）。
1.25 是听感阈值——再快发急。追问"字符预算准吗"：不准，它是语速的代理指标
（"20%" 3 字符读成 twenty percent），所以最终以 TTS 实测时长为准、并用实测
时长反推预算兜底（agent.py 的做法）。

**Q2 云端 ASR 断句怎么保证节奏对得上？**
用 verbose_json 拿字级时间戳，两条断句依据：句末标点优先、字间隙 >0.35s 兜底
（fish 等中文转录不带标点但停顿留在时间轴上）。切出的段独立翻译/配音/对齐，
节奏才能贴合原片。合并策略区分 CJK/英文（英文补空格——踩过 "Whydoit" 的坑）。

**Q3 max_tokens 隐性契约？**
OpenAI 兼容接口不带 max_tokens 时，部分网关按整个上下文预扣补全预算直接 400。
显式带 4096。引申：适配器层要吸收各供应商的隐性契约差异。

**Q4 lip-sync 为什么自建 LatentSync 不用商用 API？**
自有 5090 长期零边际成本，且数据不出内网；sync.so 效果稳但按秒计费、素材
要出内网。工程上接口先定死（apply(视频段,音频)→视频段），两条腿随时切换。
踩坑：LatentSync 要求每帧都检出人脸（转场帧会毁整段）→ 本地补丁"检不到脸
沿用上一帧人脸框" + 流水线段级回退；视频先统一 25fps（它原生 25fps 训练）。

**Q5 为什么 Dify 只做编排不做处理？**
Dify 节点有超时与大文件限制，重媒体处理（ffmpeg/lip-sync）必须留在自建服务。
Dify 的价值是可视化编排与提示词调参界面。HTTP 契约（/api/jobs 三端点）
就是为此设计的——Dify 与 React 前端共用同一套端点。

**Q6 缓存怎么设计才不会出错？**
两层防陈旧：产物按目标语言隔离（切语言不串缓存）；翻译缓存校验源文本指纹、
TTS 文件名带译文 MD5（重译/换供应商不会错拿旧音频）。踩过两个真实 bug：
切语言后翻译缓存未失效（产出中文音色读英文）、切 TTS 供应商错拿 edge 音频。

**Q7 评测怎么设计的？**
合成素材自带标准文稿与时间轴 → CER/字幕偏移可自动算；E1 消融四档
（无限长/仅限长/+atempo/+重译）隔离每个手段的贡献；CER 前做数字/标点
归一化（"两件八折"vs"2件8折"不是识别错）——归一化后 0.00~0.07。

**Q8 spill 重分类是怎么想出来的？口径改了不算作弊吗？**
来源是真实观测：Nike 片一个 0.24s 槽位的"go"每次重跑都烧 2 轮 LLM 重译仍
"溢出"。看时间轴发现它后面是 2.9s 空隙——配音本来就按起始秒定位，音频自然
延后进空隙，听感是"准时开始、停顿里收尾"，没有撞到下一句。于是把"音频尾部
撞到下一句配音/视频结尾"定义为真冲突（overflow），其余改判 spill。口径演进
在评测文档里双口径并存（未压回率/真冲突率），旧表保留可对照——消融梯度在
两个口径下都成立，只是听感口径下对比更诚实。顺带修了重译止损（无净改善即停）
和实测语速预算（静态 CPS 表换供应商会漂）。

**Q9 字幕偏移怎么从 0.16s 压到 0.04s 的？**
先把偏移量化归因：合成素材有已知时间轴，偏移逐段统计后发现是系统性偏晚
（mean 0.156s、几乎恒定）——这是语音软起音 + 云 ASR 能量门限的固有偏差，
不是随机抖动，所以适合整体前移补偿（0.12s，起止同步移、保槽位时长，
预算/对齐逻辑零扰动）。前移量受上一段终点约束（最多借完句间空隙）。
这还牵出一个缓存 bug：翻译缓存命中直接返回旧 Segment 对象，把新时间轴
静默回滚——教训是"缓存命中只借数据，不借结构"。

**Q10 六轮优化里最有含金量的工程判断是什么？**
三个。一是不信静态参数：CPS 表、时间戳偏差方向都是实测推翻的——whisper
和云 ASR 偏差方向相反（偏早 vs 偏晚），常数补偿必须带方向且按通道配置；
E6 又证明限长闭环把 LLM 差异对同步的影响压平（三模型全 0 溢出），说明
"系统结构比组件选型更能决定质量下限"。二是口径要跟着听感走：溢出改成
双口径（未压回/真冲突）后消融梯度在两个口径下都成立，改进不靠换定义。
三是真实 E2E 不可省：打桩测试全绿的系统里，Web 进度条仍卡在 5%（回调
没被透传）——接线 bug 只有端到端能抓出来。
